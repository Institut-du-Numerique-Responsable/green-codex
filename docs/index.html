Commencer dans votre projet

Pour une première installation sur macOS ou Linux, avec Git et Codex déjà installés, récupérez le dépôt puis copiez le dossier du skill. Si la destination existe déjà, consultez le guide avant de la modifier.

Depuis la racine du dépôt téléchargé :

mkdir -p ~/.agents/skills
cp -R green-codex ~/.agents/skills/green-codex

Appelez ensuite $green-codex dans votre demande. Le skill peut aussi être sélectionné automatiquement par Codex.

Récupérer le projet

Dans un terminal, depuis un dossier où vous souhaitez télécharger le dépôt :

git clone https://github.com/Institut-du-Numerique-Responsable/green-codex.git
cd green-codex

Copier le skill

Depuis la racine du dépôt, pour une première installation. Si ~/.agents/skills/green-codex existe déjà, examinez et sauvegardez vos modifications locales avant une mise à jour.

mkdir -p ~/.agents/skills
cp -R green-codex ~/.agents/skills/green-codex

Vérifier la copie

ls ~/.agents/skills/green-codex/SKILL.md

Le chemin du fichier doit s’afficher sans erreur. Cela confirme la présence du fichier ; la disponibilité du skill se vérifie ensuite dans Codex.

Utiliser Green Codex

Ouvrez votre projet dans Codex CLI ou l’extension IDE et saisissez cette demande dans Codex, sans l’exécuter dans le terminal :

Des référentiels pour guider l’action

Les règles du projet s’appuient sur des sources documentées. Elles ne constituent pas une certification de conformité.

RGESN

Écoconception des services numériques, du besoin utilisateur au cycle de vie.

GR491

Conception responsable : expérience utilisateur, code, données et hébergement.

Opquast

Qualité, compréhension et robustesse des expériences web.

RGAA

Points de vigilance sur le clavier, le focus, les contrastes et la sémantique. Un audit RGAA complet reste distinct.

Consulter les sources et leurs limites de couverture

Utile, utilisé et utilisable

Confirmer le besoin, observer les usages et vérifier que les personnes peuvent accomplir leur tâche, y compris au clavier.

Chaque dimension demande ses propres preuves. Une information manquante reste à vérifier.

La sobriété concerne aussi l’assistant

Réduire les tokens et les appels inutiles contribue au Numérique Responsable en limitant les traitements mobilisés pour un même résultat, tout en préservant la qualité.

Le gain environnemental réel dépend du modèle, de l’infrastructure et de l’usage.

Les règles NR-TOK encadrent les lectures ciblées, la réutilisation du contexte, les opérations, les modèles et la mesure des reprises.

Des preuves pour chaque constat

Le bilan indique les règles appliquées, les actions réalisées, leur intérêt, les vérifications et les limites.

Les outils statiques inclus contrôlent des motifs précis : projection SQL, lecture automatique des médias et interrogation périodique en JavaScript.

Un hook optionnel peut vérifier la structure du bilan. Son installation et sa validation de confiance sont explicites ; il ne vérifie pas la véracité des preuves.

Utiliser le bilan NR
PASS
Le point examiné est vérifié dans le périmètre annoncé.
FAIL
Un écart est constaté et accompagné d’éléments vérifiables.
REVIEW_REQUIRED
Une preuve, une vérification ou une décision reste nécessaire.

Un scan réussi ne démontre ni conformité globale ni économie d’énergie. Les évaluations distinguent format et revue du sens des réponses.
