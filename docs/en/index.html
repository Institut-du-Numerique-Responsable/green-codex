Get started in your project

For a first installation on macOS or Linux, with Git and Codex already installed, get the repository and copy the skill folder. If the destination already exists, read the guide before changing it.

From the root of the downloaded repository:

mkdir -p ~/.agents/skills
cp -R green-codex ~/.agents/skills/green-codex

Then call $green-codex in your request. Codex can also select the skill automatically.

Open the installation guide

A first request

“Review this pull request from a responsible digital perspective. Cite the files concerned, the evidence and the checks needed.”

State the scope and the expected result. A simple fix needs proportionate verification.

Get the project

In a terminal, from a folder where you want to download the repository:

git clone https://github.com/Institut-du-Numerique-Responsable/green-codex.git
cd green-codex

Copy the skill

From the repository root, for a first installation. If ~/.agents/skills/green-codex already exists, review and back up your local changes before updating.

mkdir -p ~/.agents/skills
cp -R green-codex ~/.agents/skills/green-codex

Check the copy

ls ~/.agents/skills/green-codex/SKILL.md

The file path should print without an error. This confirms the file is present; check that the skill is available in Codex afterwards.

Use Green Codex

Open your project in Codex CLI or the IDE extension and type this request in Codex, not in the terminal:

$green-codex
Review this project and suggest verifiable eco-design improvements.

If the skill does not appear, restart Codex. Read the official Codex skills documentation.

Frameworks that guide action

The project rules rely on documented sources. They are not a compliance certification.

RGESN

Eco-design of digital services, from user need to lifecycle.

GR491

Responsible design: user experience, code, data and hosting.

Opquast

Quality, clarity and robustness of web experiences.

RGAA

Safeguards for keyboard use, focus, contrast and semantics. A full RGAA audit remains separate.

See the sources and their coverage limits

Useful, used and usable

Confirm the need, observe actual use and check that people can complete their task, including with a keyboard.

Each dimension needs its own evidence. Missing information stays to be verified.

Responsible digital guides

These guides are written in French.

  • Apply the NR charter
  • Responsible architecture with BP-AIR
  • Stakeholder maturity
  • Responsible AI questions with RIA31

RIA31 is distinct from the EU AI Act. Generated documents do not prove that an organisation has adopted the practices.

Sobriety applies to the assistant too

Reducing unnecessary tokens and calls supports responsible digital practice by limiting the processing used for the same result, while preserving quality.

The actual environmental gain depends on the model, the infrastructure and the use.

The NR-TOK rules cover targeted reads, context reuse, operations, models and measuring rework.

Read the Codex sobriety guide

Rules inspired by and adapted from Caveman, by Julius Brussee. The INR extensions are documented.

Evidence for every finding

The summary lists the rules applied, the actions taken, why they matter, the checks and the limits.

The included static tools check specific patterns: SQL projection, media autoplay and periodic polling in JavaScript.

An optional hook can check the structure of the summary. Its installation and trust review are explicit; it does not check whether the evidence is true.

Use the NR summary
PASS
The item reviewed is verified within the stated scope.
FAIL
A gap is found and backed by verifiable evidence.
REVIEW_REQUIRED
Evidence, a check or a decision is still needed.

A passing scan proves neither overall compliance nor energy savings. The evaluations separate format checks from review of what the answers mean.
